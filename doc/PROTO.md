# Структура сообщения

## Синтаксис

_u8an_ — UTF-8 alphanumerical symbol
_u8p_ — UTF-8 printable symbol
_name_ = _u8an_ +
_kv list_ = (`RS` _kv pair_) *
_kv pair_ = _name_ `US` _value_
_value_ = `0x00` (7 byte integer) | `0xFF` (7 byte negative integer) | _u8p_ *

## Структура

### Сигнатура

`0xC6 0x97` (msg type, 1 byte) (flags, 1 byte) (proto version, 4 bytes)

### Заголовок

`SOH` (msg id, 7 bytes, 7 least bytes of UNIX time in ms)
`RS` (sender _name_)
`RS` (recepient _name_)
(_kv list_)

**NB**: тройка (msg id, sender, recepient) должна быть уникальной для каждого отдельного сообщения

### Тело сообщения

`STX` (data) `ETX` (CRC-32/POSIX of data) `EOT`

## Типы сообщений

От типа сообщения зависят некоторые другие поля

| Тип | Описание | Примечания |
|:---:| :---     | :---       |
|`01`| Технический пакет | Keep-alive, probing, ACK/NAK |
|`02`| Промежуточный пакет | Часть сообщения; у всех многопакетных сообщений одинаковый msg id |
|`03`| Текст | Может содержать SGR форматирование |
|`04`| Двоичный файл с сигнатурой | Обязан иметь размер в заголовке |
|`05`| Двоичный поток без сигнатуры | Обязан иметь размер и тип в заголовке |
|`06`| Magnet ссылка на файл | |

## Флаги

Флаги описывают что было сделано с телом data.

Порядок модификации — от старшего к младшему.

|Флаг|Значение|Поведение по умолчанию|Ключ|
|:---:|:---:|:---:|:---:|
|`01`|Зашифровано|X25519 XChaCha20 Poly-1305|`E`|
|`02`|Подписано|Ed25519 для цельных, Ed25519ph для разбитых на части|`S`|
|`04`|Сжато|DEFLATE|`C`|

Подпись и сжатие применяется к телу целиком, пакеты шифруются индивидуально.

Подпись всегда добавляется в конец сообщения.

## Общие заголовки

Заголовки необязательны, но могут упростить жизнь.

| Ключ | Формат значения | Смысл |
| :---: | :---: | :--- |
| `L` | Положительное целое | Длина данных сообщения в байтах в этом пакете после всех преобразований |
| `R` | Положительное целое | Длина данных всего сообщения в байтах до применения разбиения на части, сжатия, подписи и шифрования |
| `splat` | Положительное число | Количество промежуточных пакетов, содержащих это сообщение |
| `mime` | Строка | MIME type содержимого |

## Технические пакеты

Используются для установления и поддержания связи.

### Keep alive

В заголовке содержится ключ `got`, в значении которого находится количество msg id в теле

Тело состоит из списка msg id, полученных отправителем от получателя с момента отправки предыдущего Keep alive пакета.
msg id выровнены по 8 байт. Список может быть пуст.

Используется для поддержания соединения.

### Probing

В заголовке содержится ключ `s`, в значении которого лежит длина всего пакета в байтах как положительное число.

В теле пакета содержится строка из байт `0x21`-`0x7E`, повторённая столько раз, сколько влезет.
Длина строки определяется заголовком.
Пакет обязан иметь 0 в младших трёх битах флага.

Используется для проверки максимального размера пакета на маршруте.

### Resend request

В заголовке содержится ключ `rere`, в значении которого msg id.
Также может содержаться ключ `part`, в значении которого количество частей сообщения, которые необходимо переотправить.

Тело содержит номера частей, выровненных по 8 байт. Количество должно совпадать со значением ключа `part`.

Используется для запроса переотправки повреждённых или потерянных промежуточных сообщений.

### Papers, please

В теле сообщения содержится информация об используемом клиенте в формате JSON. 
Все поля опциональны. Все строки в UTF-8.

 - `proto`: `[integer]` поддерживаемых версий протокола
 - `crypt`: `[string]` поддерживаемых методов шифрования
 - `sign`: `[string]` поддерживаемых методов подписи
 - `compress`: `[string]` поддерживаемых методов сжатия
 - `name`: `string` название клиента
 - `ver`: `string` версия клиента
 - `os`: `string` ОС, на которой запущен клиент
 - `time`: `string` ISO 8601 время клиента
 - `freeform`: `any` что угодно, потому что почему бы и нет

Используется чтобы объяснить второй стороне с кем она имеет дело. Например, для согласования протокола.

## Промежуточный пакет

В заголовке любого пакета, кроме технического и промежуточного, может содержаться заголовок `splat`,
в значении которого указано количество промежуточных сообщений, которые содержат данные для этого сообщения.

В заголовке промежуточного сообщения `pn` указывается номер пакета.
Разбиение и сборка происходят в следующем порядке: 
&lt;нормальный пакет&gt; 
&lt;промежуточный с `pn`=0&gt; 
&lt;промежуточный с `pn`=1&gt; … &lt;промежуточный с `pn`=(`splat` - 1)&gt;. 
Сжатие, шифрование и подпись применяются ко всему сообщению целиком, до разбиения.
Для двоичных, зашифрованных и сжатых данных обязательно указывается заголовок `L`.

## Текст

В заголовке может содержаться ключ `st`, значение которого уквазывает MIME subtype с дополнениями.
По умолчанию считается `x-ansi;charset=utf-8`, т.е. текст в UTF-8, содержащий ANSI escape.

Дополнительно можно указать `cs`, по умолчанию UTF-8.

Тело сообщения содержит сам текст непосредственно.

## Двоичный файл с сигнатурой

Заголовок `L` обязателен.
Допускается заголовок `filename`.

Допускается передача файлов, имеющих общеизвестную сигнатуру, таких как ZIP (`PK`), DOS/NE/PE exe (`MZ`), ELF (`0x7F ELF`), GIF (`GIF87a` / `GIF89a`), JPEG, PNG и других.

Файлы без сигнатуры (например, текст) должны использвать `03`, `05` или `06`.

## Двоичный файл без сигнатуры

Заголовки `L` и `mime` обязательны.
Допускается заголовок `filename`.

Тело может содержать что угодно, подходящее по MIME типу.

## Magnet ссылка

Ссылка на торрент с файлом. Отправляющий обязан встать на раздачу.
